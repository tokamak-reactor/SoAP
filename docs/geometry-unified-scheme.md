# Единая схема геометрии SoAP: structured ↔ unstructured

Решение принято 06.08.2026 после чтения официальной документации
(b2cdca.F / b2cdcv.F для обеих версий) и проверки на реальных watch'ах.

Принципы:
1. **Вершины первичны.** В обеих версиях первичные данные сетки — вершины:
   STR — crx/cry (4 угла на ячейку, с дублированием), UNSTR — vxX/vxY.
   Пси и B-функции тоже на вершинах: fpsi/ffbz (STR), vxFpsi/vxFfbz (UNSTR).
2. **Центры ячеек** — НЕ унифицируются тривиально:
   - STR: cv = mean(4 углов) — точно (ячейки ~параллелограммы; проверено diff=0)
   - UNSTR: cvX/cvY ЧИТАТЬ из файла (b2ag считает иначе, чем mean(вершин);
     проверено: расхождение до 0.53 м; там есть треугольники и вырожденные ячейки)
3. **Середины граней** — универсально: fc = mean(2 вершин грани), точно
   в любом типе сетки (грань — отрезок).
4. **Потоки** — в UNSTR на гранях (1:nFc), в STR на ячейках со сдвигом.
   В SoAP приводим ОБА к граням (1D, nFc): STR через imap_fcx/imap_fcy,
   UNSTR напрямую. Это уже реализовано (variable_catalog).
5. **Расстояния от сепаратрисы** — единый физический способ (ходьба по
   центрам ячеек вдоль флакс-трубки, накопление евклидовых расстояний);
   накопление hy (y2, Matlab_SPb) — опция x_coord="y2" для совместимости
   со старыми графиками. Для ортогональной STR-сетки оба способа почти
   совпадают (ортогональность гарантирует b2ag); различие — в диверторе.

## Что делать (план)

1. **Починить fc_x/fc_y для STR** — баг сдвига индексов в _load_structured_grid
   (fc_x[i] = mean(vx_x[fc_vx[i+1]]), все 6304 грани). После: fc_x == mean(vx).
2. **Проверить знак bb в STR** — нужен ли np.abs; в unstr cvBb уже abs.
   (Для поиска экваторов по экстремумам |Bz| abs удобен — проверить
   согласованность с Matlab_SPb nout/nin.)
3. **Проверить gs ↔ fc_s для STR** — площади граней (gsx/gsy) vs fc_s.
4. **Проверить cv_fpsi для STR** — как усредняем 4 вершины fpsi.
5. **Единый cv_r/cv_theta** — физическая ходьба по центрам (обе сетки);
   x_coord="y2"/"x2" — накопление hy/hx как опция совместимости.
6. **Таргеты/сепаратриса под едиными именами** — STR: строки матрицы;
   UNSTR: топология. (geometry-structured-map.md, разделы D/F.)
7. **fs_psi для обеих сторон** — psi на флакс-поверхностях (для psi_norm).
8. **Стенка**: для STR — честный отказ (или внешний .ogr); для UNSTR —
   fcLbl-сегменты.

## Ключевые факты из документации (для справки)

- STR: «первичные данные — координаты 4 вершин всех ячеек (crx/cry);
  метрика (vol, hx, hy, qz, qc, gs) ПРОИЗВОДНА от них». fpsi/ffbz на вершинах.
- UNSTR: «первичные данные — координаты вершин И центров ячеек».
  vxFpsi/vxFfbz на вершинах. fcX/fcY нет — середины граней производные.
- x = полоидальное, y = радиальное (STR). Знак потоков: + в сторону роста индекса.
- Потоки: STR (nx+2,ny+2,0:1,ns) на ячейках со сдвигом; UNSTR (nFc,0:1,ns) на гранях.
- cvBb (UNSTR): компоненты неотрицательны (0 ≤ cvBb), направление — cvEb.
- fcHc (UNSTR): расстояния от центров ячеек fcCv до центра грани (в файле).
- fsPsi (UNSTR): Psi на флакс-поверхностях + psi_increasing (направление роста).
- isClassicalGrid + imap*: для сеток, производных от structured.

## PSI-координата (решение от 06.08.2026)

**Проблема**: fpsi в b2fgmtry может быть нулями:
- STR (проверено на Globus_44644): fpsi = ВСЕ НУЛИ (0 из 13600)!
  Наш код делал подмену `cv_fpsi = cv_ft` (номер флакс-трубки!) — УБРАТЬ.
- UNSTR (проверено на Globus-3_WG): vxFpsi ненулевая (−0.107..0.237,
  сепаратриса ≈ 0). Но в других расчётах может быть нулями.
- Файл равновесия .equ (g044846.00185.x2.equ): psi уже хранится как
  (psi−psib), psib=0, сепаратриса=0, единицы Wb/rad, значения −0.021..+0.018.

**Источники psi (единая схема):**
| Приоритет | Источник | Когда |
|---|---|---|
| 1 | b2fgmtry vxFpsi/fpsi | **по умолчанию всегда** (UNSTR: vxFpsi есть — работает без equ) |
| 2 | .equ файл равновесия | опционально: если fpsi нули И пользователь передал путь |

**Поведение по умолчанию (решение пользователя 06.08.2026):**
- Читаем psi из b2fgmtry всегда (STR: fpsi, UNSTR: vxFpsi).
- Если fpsi ВСЕ нули (типичный STR-случай): **отключаемое предупреждение**
  в консоль (warnings.warn с категорией — подавляется стандартно),
  psi_source = None, cv_fpsi/fc_fpsi = None (БЕЗ подмены на cv_ft!).
- Пользователь МОЖЕТ передать путь к equ-файлу
  (например, `watch.compute_psi(equ_path=...)` или аргументом) — тогда
  psi строится из .equ (порт psi_norm.m).
- **Будущая надстройка поиска файлов** (отдельный модуль, не сейчас):
  сама ищет .equ на уровень выше watch / в baserun и передаёт путь.
- UNSTR: vxFpsi есть — equ не нужен (но если вдруг нули — тот же fallback).

**Единые переменные**: vx_psi, fc_psi, cv_psi, fs_psi в обоих вариантах:
- fc_psi = mean(psi вершин грани) (как matlab_wg: fcFpsi = mean(vxFpsi(fcVx),2))
- cv_psi: STR = mean(4 углов fpsi); UNSTR = intcell_us(fc_psi) (как matlab_wg)
- fs_psi: UNSTR из файла (fsPsi); STR вычислить (среднее по поверхностям)
- Если psi из .equ: интерполяция на сетку (порт psi_norm.m: сплайн psi(R),
  R_SOLPS из углов ячеек) — по сути даёт psi на ячейках/вершинах, дальше та же схема.

**Нормировка (выбор пользователя, стандарт сообщества):**
```
psi_N = (psi − psi_axis) / (psib − psi_axis)
```
- psi_axis = min(psi) — магнитная ось; psib — psi на сепаратрисе (0 в equ/UNSTR)
- **0 на оси, 1 на сепаратрисе, > 1 в SOL** (как psi_norm.m)
- Инвариантна к масштабу и сдвигу → работает для любых единиц.
- Для графиков: x_coord="psi_n" (нормированная), сырая psi — диагностика.

**Убрать**: подмену cv_fpsi = cv_ft в geometry_reader (это номер трубки,
не psi). Вместо неё: cv_fpsi/fc_fpsi = None + флаг psi_source:
"b2fgmtry" | "equ" | None. (Квантити, которым нужен psi, должны явно
проверять источник.)
